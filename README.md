# soen — разбор референсов и дизайн-система

Разбор трёх референсов и собранная из них рабочая система: первый экран
кафе, где выбор вкуса происходит сразу на герое, а фон анимирован
процедурно, без фотографий.

## Что внутри

| Файл | Что это |
| --- | --- |
| `src/index.html` | Рабочий первый экран: анимированный фон, дуга выбора, морфинг напитка |
| `src/design-system.html` | Разбор kumo / tempo / lumen с измеренными числами + сама система |
| `build/inline_fonts.py` | Сборка: вшивает subset-шрифты в страницы как data-URI |
| `build/*.woff2` | Prata, Golos Text, JetBrains Mono — subset Latin + Cyrillic |
| `dist/` | Собранные самодостаточные страницы |

## Сборка

```sh
python3 build/inline_fonts.py
```

Скрипт берёт каждый файл из `src/`, подставляет `@font-face` с base64
вместо маркера `/*@FONTS@*/` и пишет результат в `dist/`. Страницы в
`dist/` не тянут ни одного внешнего ресурса — целевая площадка блокирует
внешние хосты, и ссылка на шрифтовой CDN молча свалилась бы в подстановку.

## Откуда взялись числа

Все размеры в разборе не на глаз: видео-референс разложен на кадры
(`800×600`, 540 кадров, 60 fps) и промерен по пикселям — отступы, радиусы,
цвета, позиции карточек. Радиус дуги получен подгонкой параболы к
координатам центров карточек: `R = 900 px` в пересчёте на ширину 1440,
шаг между соседями `18°`.

## Проверено

Chromium, ширины 390 / 834 / 1280 / 1440 / 1600:

- нет горизонтального переполнения;
- нет ошибок в консоли;
- все три гарнитуры грузятся (не подстановка);
- `prefers-reduced-motion` — фон рисуется одним статичным кадром,
  страница остаётся рабочей;
- геометрия адаптивная: до 700 px дуга уходит под стакан, а не
  просто масштабируется.

## Перенос на другое меню

Меняются три вещи: массив `FLAVOURS` (название, слуг, цена, акцент,
четыре цвета полос, три доли границ), шесть рисованных марок и рампа
фона в токенах. Геометрия дуги, тайминги и компоненты не трогаются.

## Видео со страницы

Встроенный экспорт видео падал на `executeJavaScript timed out (5s)`: он ждёт
ответа от страницы, а та в этот момент держит главный поток — распаковка
бандла, вёрстка, первый кадр canvas. `tools/record-page-video.js` ничего у
страницы не спрашивает: браузер сам пишет screencast, сценарий ведётся кликами
изнутри страницы, а кадр режется по реальному прямоугольнику макета.

```sh
node tools/record-page-video.js \
  --url file:///abs/path/page.html \
  --width 2088 --height 1164 \
  --crop ".artboard" \
  --click ".flavour-card" --dwell 3200 \
  --out out.mp4
```

| Флаг | Что делает |
| --- | --- |
| `--crop` | селектор области кадра; берётся её живой `getBoundingClientRect` |
| `--click` | селектор шагов сценария: скрипт обходит их по очереди |
| `--dwell` | сколько держать каждый шаг, мс |
| `--patch` | файл с JS, который выполняется на странице перед записью |
| `--seconds` | длительность, если сценария нет и надо просто снять анимацию |

Нужны `playwright` и ffmpeg с libx264 (`npm i ffmpeg-static`) — тот, что идёт с
Playwright, собран только с VP8, и на нём скрипт отдаёт webm вместо mp4.
