# Мастерская Гордеева — сайт

Заказы, личные задачи, финансы и загрузка. Открывается с телефона и с
компьютера по одной ссылке. Данные лежат в общей базе: правку с одного
устройства остальные видят сразу, без перезагрузки.

Все даты и часы — московские, независимо от часового пояса устройства.

## Файлы

| Файл | Что это |
| --- | --- |
| `index.html` | Вся страница: разметка, стили, логика |
| `config.js` | Адрес и публичный ключ общей базы |
| `db/schema.sql` | Таблицы, права и функции записи для Supabase |
| `db/set-code.sql` | Задать общий код доступа |
| `db/seed.sql` | Перенести стартовые заказы в базу (по желанию) |
| `data/state.json` | Запасные данные, когда база не настроена |
| `vendor/supabase.js` | Клиент Supabase 2.112.4, лежит в репозитории |
| `manifest.webmanifest`, `sw.js`, `icon*` | Установка «на экран Домой» и работа без сети |

## Как устроен доступ

- **Смотреть** может каждый, у кого есть ссылка. Ничего вводить не нужно.
- **Менять** — после ввода кодового слова (кнопка «Ввести код» в шапке).
  Код проверяется базой и остаётся в браузере этого устройства; на новом
  устройстве его вводят один раз.

Без кода страница показывает данные в режиме чтения: кнопки создания и
удаления скрыты, поля заказа заблокированы.

Технически: таблицы закрыты политиками RLS, прямой записи нет ни у кого.
Запись идёт только через функции `hb_save_order`, `hb_delete_order`,
`hb_save_task`, `hb_delete_task`, и каждая сверяет код с bcrypt-хэшем в
таблице `hb_secret`, которую снаружи не прочитать. Публичный ключ `anon`
в `config.js` лежит открыто — так и задумано, сам по себе он не даёт
ни записи, ни доступа к секретам.

## Настройка базы (один раз)

1. Создать проект на [supabase.com](https://supabase.com) (бесплатного тарифа хватает).
2. **SQL Editor** → вставить и выполнить `db/schema.sql`.
3. Там же выполнить `db/set-code.sql`, заменив `СЛОВО` на свой код доступа.
4. По желанию — `db/seed.sql`, чтобы в базе появились стартовые заказы.
5. **Project Settings → Data API** → скопировать `Project URL` и ключ `anon`
   и вписать их в `config.js`:

   ```js
   window.HB_CONFIG = {
     supabaseUrl: "https://ваш-проект.supabase.co",
     supabaseAnonKey: "eyJ..."
   };
   ```
6. Закоммитить `config.js` и запушить в `main` — сайт пересоберётся сам.

Сменить код позже — снова выполнить `db/set-code.sql` с новым словом.
Старый код перестанет подходить, и страницы, где он был сохранён,
сами вернутся в режим чтения.

Пока `config.js` пустой, сайт работает по-старому: показывает
`data/state.json`, а правки держит в памяти браузера, только у вас.

## Локальный просмотр

```sh
python3 -m http.server 8000 --directory site
```

и открыть <http://localhost:8000>.

## Публикация

Ветку `main` публикует GitHub Actions (`.github/workflows/pages.yml`) в
GitHub Pages. Один раз нужно включить Pages: **Settings → Pages → Source:
GitHub Actions**. Дальше каждый push в `main`, который трогает `site/`,
обновляет сайт.

## Проверено

Схема — на живом PostgreSQL 16 с ролями `anon` / `authenticated`:
чтение открыто всем, прямая запись и таблица секретов недоступны,
неверный код отклоняется, верный — пишет и удаляет; скрипты можно
запускать повторно.

Страница — в Chromium на 390 / 768 / 1440: горизонтального переполнения
нет нигде, включая открытые окна; правка с другого устройства приезжает
без перезагрузки; код помнится между визитами; «Забыть код» возвращает
режим чтения; дата и приветствие остаются московскими при часовом поясе
устройства в Лос-Анджелесе и Владивостоке.
